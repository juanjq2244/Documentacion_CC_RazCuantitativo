# 2.2. Requerimientos

## **2.2.1. Reglas de Negocio**

Las reglas de negocio son directrices o restricciones propias de las organización que modelan como opera el negocio.

* **Limitaciones del Sistema:**
    * **REG-NEG-001:** El sistema se despliega en un PC sin conexion a internet y de forma local.

* **Respuesta Estímulo**
    * **REG-NEG-002:** Cada *sesión* debe corresponder al identificador enviado por el **Componente Centralizador** al ingresar.
    * **REG-NEG-003:** Cada respuesta de un estímulo debe estar asociada a una sesión y estímulo existentes.
    * **REG-NEG-004:** Los intentos por estímulo deben ser un valor entero no negativo.
    * **REG-NEG-005:** El tiempo restante al completar un estímulo debe ser un valor flotante no negativo.

* **Tutorial Tarea/Nivel**
    * **REG-NEG-006:** Cada mensaje de tutorial debe tener contenido no vacío *(máximo 500)*.
    * **REG-NEG-007:** Los mensajes de tutorial deben tener un índice secuencial único dentro de su contexto.
    * **REG-NEG-008:** Cada tutorial debe estar asociado a una tarea/nivel existente.

* **Tarea**
    * **REG-NEG-009:** Un estudiante solo puede realizar *una tarea* a la vez.
    * **REG-NEG-010:** Cada *tarea* debe tener un identificador único y corresponder a uno de los 4 juegos de **Razonamiento Cuantitativo**.
    * **REG-NEG-011:** El nombre de cada tarea debe ser único en el sistema.

* **Nivel**
    * **REG-NEG-012:** Un nivel pertenece exclusivamente a *una sola* tarea.
    * **REG-NEG-013:** Cada *nivel* debe tener un identificador único, dificultad específica y estar asociado a una única tarea.
    * **REG-NEG-014:** La intensidad del nivel debe estar en el rango de 1 a 3.
    * **REG-NEG-015:** No pueden existir dos niveles con la misma intensidad para la misma tarea.

* **Estímulo**
    * **REG-NEG-016:** Un estímulo pertenece exclusivamente a *un solo* nivel.
    * **REG-NEG-017:** Cada estudiante tiene tres vidas para completar los estímulos de cada tarea.
    * **REG-NEG-018:** Cada *estímulo* debe tener un identificador único y estar asociado a un único nivel.
    * **REG-NEG-019:** Cada *estímulo* debe tener asociada una respuesta correcta válida.
    * **REG-NEG-020:** El tiempo límite para desarrollar un estímulo debe ser un valor entero no negativo.
    * **REG-NEG-021:** La pregunta del estímulo debe tener menor o igual 1500 caracteres.
    * **REG-NEG-022:** La combinación de estimuloId, tareaId, nivelId y sesionId debe ser única.

* **Opciones de Respuesta**
    * **REG-NEG-024:** Una opción de respuesta pertenece exclusivamente a *un solo* estímulo.
    * **REG-NEG-025:** La combinación de estimuloId y opcionId debe ser única.

## **2.2.2. Requerimientos Funcionales**

Estos describen lo que el sistema debe *hacer*, clasificados por el rol que realiza la acción.

* **Gestión de Autenticación y Sesión**
    * **REQ-FUN-001:** El sistema debe recibir los datos de la sesión del **Componente Centralizador** al ingresar.

* **Gestión de Tareas y Navegación**
    * **REQ-FUN-003:** El sistema debe presentar un menú de selección con las 4 tareas de **Razonamiento Cuantitativo**.
    * **REQ-FUN-004:** El sistema debe permitir al estudiante seleccionar e ingresar a una tarea específica.

* **Gestión de Progreso y Persistencia**
   * **REQ-FUN-005:** El sistema debe guardar automáticamente el progreso del estudiante, incluyendo la tarea actual en curso, y el estímulo actual de una tarea.
   * **REQ-FUN-006:** El sistema debe recuperar el último progreso guardado al reiniciar la pagina.

* **Interacción con Contenido**
   * **REQ-FUN-007:** El sistema debe permitir la interacción mediante teclado (teclas W/A/S/D) para actividades específicas.
   * **REQ-FUN-008:** El sistema debe permitir la interacción mediante mouse para completar actividades e interactuar con la aplicación.
   * **REQ-FUN-009:** El sistema debe mostrar tutoriales contextuales antes de iniciar tareas y niveles.
   * **REQ-FUN-010:** El sistema debe gestionar el flujo de mensajes tutoriales (siguiente, anterior).

* **Gestión de Respuestas y Evaluación**
   * **REQ-FUN-011:** El sistema debe capturar y almacenar *las respuestas del estudiante* al final de cada estímulo.
   * **REQ-FUN-012:** El sistema debe validar las respuestas a comparacion de la opción correcta definida.
   * **REQ-FUN-013:** El sistema debe gestionar *el contador de vidas* del estudiante (3 vidas por tarea).
   * **REQ-FUN-014:** El sistema debe aplicar *límites de tiempo* para completar estímulos cuando corresponda.

## **2.2.3. Requerimientos No Funcionales**

Estos describen *cómo* debe funcionar el sistema, definiendo sus cualidades y restricciones.

* **Disponibilidad / Confiabilidad**
   * **REQ-NOFUN-001:** La *base de datos* local debe tener una disponibilidad del 99.99% durante el tiempo de ejecución.

* **Mantenibilidad / Extensibilidad**
   * **REQ-NOFUN-002:** La arquitectura debe permitir la modificación rápida de módulos y objetos para corrección de errores.
   * **REQ-NOFUN-003:** El código debe estar modularizado para facilitar el mantenimiento de cada tarea y actividad por separado.
   * **REQ-NOFUN-004:** El sistema debe permitir la adición de nuevas tareas sin afectar el funcionamiento existente.

* **Usabilidad / Experiencia de Usuario**
   * **REQ-NOFUN-005:** La *interfaz* debe ser intuitiva y fácil de navegar para estudiantes de diferentes niveles académicos.
   * **REQ-NOFUN-006:** Los *tutoriales* deben ser claros y suficientes para entender cada tarea sin asistencia externa.

* **Compatibilidad / Integración**
   * **REQ-NOFUN-007:** El *sistema* debe ser compatible con el formato de datos de otras variables de Cognicare.
   * **REQ-NOFUN-008:** La *estructura de datos* debe permitir la exportación e importación de progreso entre sesiones.
   * **REQ-NOFUN-009:** El *sistema* debe operar en ambiente web sin requerimientos adicionales de software.

* **Rendimiento**
   * **REQ-NOFUN-010:** La *aplicación* debe consumir menos del 80% de los recursos de CPU durante ejecución normal.
   * **REQ-NOFUN-011:** El *uso de memoria* no debe exceder 500MB durante la ejecución.

* **Seguridad**
   * **REQ-NOFUN-012:** Los *datos de progreso* deben estar protegidos contra modificaciones no autorizadas.
   * **REQ-NOFUN-013:** Las *credenciales necesarias de la sesion*, recibidas del **Componente Centralizador**, deben almacenarse de forma segura al iniciar.
